Prepare the review

Start the shipping-exception review with a narrow question

This resource is designed to produce a shipping exception diary entry recording the event, constraint, affected step, boundary, and next owner. Begin with latest visible event, parcel or order context, dated constraint wording, affected step, and reviewer owner. Keeping the question narrow prevents unrelated rows and changing platform details from being mixed into one conclusion.

Write down the decision you are trying to make before opening additional sources. A good question can be answered with a specific record, while a vague request such as “check everything” creates no reviewable result.

  • Name one row, source, or field set that is in scope.
  • Capture the exact visible wording instead of relying on memory.
  • Add an observation date so a later reviewer can distinguish old evidence from current evidence.

Working method

Compare identity, selection, evidence, and time

First confirm that the saved row and the live source refer to the same thing. Then compare the exact selection, option, or field wording. Only after those checks should visible evidence be used to support a decision.

Treat time as part of the evidence. Price, stock, images, policies, and source paths can change, so this page records what was observable during a review rather than promising a permanent state.

  • Identity: preserve the source path and enough context to reopen it.
  • Selection: copy the option, size, label, or field wording exactly.
  • Evidence: separate visible facts from interpretations and open questions.
  • Time: record when the observation was made and when it should be rechecked.

Worked example

Turn a mismatch into a useful record

Example: a note mentions a route delay but not the parcel; it is retained as context while parcel impact remains unresolved. The useful result is not a confident-sounding label; it is a note that another reviewer can reproduce without guessing what happened.

The record should state which evidence was accepted, which detail remained unresolved, and why the next action is appropriate. If a new observation later changes the decision, retain the earlier dated note instead of silently overwriting it.

  • Accepted evidence and its source path.
  • Rejected or conflicting evidence with a short reason.
  • The decision owner and one next review date.

Stop rule

Pause when the evidence cannot support the decision

If the event cannot be tied to the same order or parcel, do not present it as that shipment's status.

A pause is a valid output. It protects the LitBuy Spreadsheet review from turning missing information into an unsupported claim and tells the next reviewer exactly what must be resolved.

  • Do not infer an unavailable field from a similar row.
  • Do not treat a redirect, cached image, or old note as proof of a current state.
  • Do not erase the earlier observation when recording a replacement.
